# 015 · 向 `dsh-vanish-agents` 学什么

来源：`@local/dsh-vanish-agents` 0.1.0（Vanish 智员管理台，77 文件 / 零依赖 ESM / 无构建），
作者把它做成 **DSH 插件**：Host 半边管连接、凭据、路由，浏览器半边管面板。文档三件套
（`docs/DESIGN.md` 441 行、`docs/VERIFICATION.md` 1581 行、`README.md`）写得比代码还细。

它和我们**连的是同一个网关**（`wss://<内部网关域名>/vanish-agent/ws`），但站在另一侧：
它解决"人 → 智员"的接入与对话质量，我们解决"工单 → 分支 → PR"的交付链路。所以它不是竞品，
是一份现成的、被 27 轮验证打磨过的问题清单。

---

## 0. 顺带破掉的悬案：`im` 源为什么四天里一天一断

读它的 DESIGN §2 时看到两条事实，正好对上我们这几天的日志：

```
网关  wss://<内部网关域名>/vanish-agent/ws
DNS   <内网私有地址>        ← 私有地址
```

本机实测：

| 观测 | 值 |
|---|---|
| 目标域名解析 | `<内部网关域名> → <内网私有地址>`（内网） |
| 同域公共记录 | `<公司域名> → <公网地址>`（公网可达） |
| 本机网卡 | `WLAN <公司网段地址>/16`，DNS `<内网 DNS 1>, <内网 DNS 2>` |

**结论：这个网关是分域 DNS，只在公司内网内解析。** 机器换到家里网络
（`<家用网段>`，DNS 指向路由器）时，权威侧对这个名字就是 NXDOMAIN —— 不是对方 DNS 抽风，
是我们换了网络。这解释了四天里"断→恢复→再断"的全部节律，也解释了为什么 `open.feishu.cn`
同期也会失败（同一时刻整体换网）。

我们的 `im` 源把这件事报成了 `The bridge failed: ... ENOTFOUND`，让人以为是服务端故障。
**这是第一个该抄的教训：错误要能指向动作。**

## 1. 它的骨架（只记我们缺的部分）

### 1.1 半边划分

| 半边 | 负责 | 我们对应物 |
|---|---|---|
| Host（插件进程内） | 凭据（`ctx.credentials`，绝不进配置/状态文件）、连接池、消息路由、诊断、KB 落盘 | `src/sources/**` + `src/app/**` |
| Client（浏览器） | 只渲染 + 发起操作，**拿不到 token**，二维码原样渲染不拼参数 | `src/client/**` |
| 共享服务 | 一份 Host service + 两条薄封装（UI 与 agent 工具都能用） | `src/app/http.ts` |

### 1.2 连接状态机（`lib/connection.js`）

六个状态 `idle / connecting / online / backoff / needs_rebind / disabled`，关键设计：

- **`#once()` 只在 socket 关闭时 settle**，握手成功不 resolve —— 否则重连循环会在健康连接上再开一条，
  被网关 `4001` 踢（他们的原 bug，写进了 VERIFICATION 14.2②）。
- **心跳看门狗**：`tick` 15s 一次，**2.5×interval 没收到就强关重连**。
- **出站串行**：`writeChain` 串成一条 Promise 链；失败不污染链，但调用方仍拿到 reject。
- **帧上限** 256 KiB，超了**报错而不是静默截断**。
- **pending request 表**：每请求 15s 超时；连接关闭时**全部置失败**，不复用旧连接的成功响应。
- **退避**：`1s→2s→4s…`，上限 30s，抖动 ±30%；**全局闸门 4 次/秒**（12 个智员 3 秒内全部发起，
  1/s 时最后一个要等 12 秒）。
- **`needs_rebind` / `disabled` 不再自动重连** —— 鉴权错和"被另一实例踢"都不是重试能解决的。

### 1.3 消息语义（`lib/protocol.js`）

- `eventId` **有界 LRU 2000**；命中只重发 ACK，**绝不重跑一轮**。
- **只有消息真正提交进本地队列才 ACK**；提交失败不 ACK，让网关重投。
- 入站校验逐字段（`conversationId` 是硬边界，**禁止解析格式**、禁止用 `userCode`/`groupId` 当主键）。
- 群聊背景：每群保留 **最近 20 条 / 12 小时**，只在被 @ 那一轮拼进上下文，并明写
  "这些消息没有 @ 你，不要逐条回应"；非文本只记 `［图片］`，**不留 URL**（防被当抓取线索）。

### 1.4 延迟与拟人化（`lib/humanize.js`）

| 阶段 | 承诺 | 实现 |
|---|---|---|
| 收消息 → ACK | ≤100ms | 接收循环只做"校验 + 入队" |
| → typing | ≤1.2s | `agent.command.send typing`，ttl 5s / 每 4s 续 |
| → 首段正文 | ≤2.5s | 未完成也发，≥80 字符或自然断句（段落→句号→逗号） |
| 单条消息 | ≤1200 字符 | 超出分段，段间 ≥400ms |

两个反直觉决定值得抄进我们自己的 IM 回复策略：

1. **合并窗口 1.5s 砍到 300ms** —— 防刷屏的窗口直接把首响吃掉了。
2. **时间/发送者/群名一律进用户消息体，不进 system prompt** —— 否则每轮前缀都变，KV 缓存全废，
   "这是 TTFT 最大的隐形杀手"。

### 1.5 知识库（`lib/kb.js`）

- 条目落盘成 `entries/<id>.md`（YAML-ish front matter + 正文），人能用编辑器改、模型能 `read`/`grep`。
- 每一轮只带 **入口**（≤1200 字 / 40 条：标题、标签、字数 + "不要凭标题猜内容"）；
  匹配命中才把正文拼到这一轮末尾（≤2 条、单条 1800 字、合计 2400 字）。
- **打分只看标题与标签**（标签 3 分 / 标题词 2 分，低于 3 分不带）—— 正文参与打分会让每条都命中每条。
- 提取走"候选 ≠ 条目"：模型产出先落 `kb/candidates.json`，**人工采纳**后才进提示词；
  采纳时按标题 bigram Jaccard ≥0.6 去重。理由写得很直白：**知识库是全局的，一条编造的事会污染所有智员。**

### 1.6 转派（替身 / 工人）

替身按"领域 + 路由关键词"**每轮现场渲染**派工清单（加人不改人设），输出机器可读标签
`<dispatch to="…">任务</dispatch>`；工人是绑定各自工作区的 DSH 会话，结果只回替身，替身整合后
才发给用户。边界：单轮 ≤4 个目标、单条 ≤3 轮、worker 6 分钟超时、同 worker 串行、
转派自己在日志里可见（`type=DISPATCH` 一行）。

## 2. 该抄的（按我们能落地的优先级）

### P0 —— 直接对着我们踩过的坑

| # | 抄什么 | 我们的现状 | 落点 |
|---|---|---|---|
| 1 | **错误文案分层**：内部异常 → 五类可执行原因（没配模型 / 连接断了 / 太频繁 / 上下文太长 / 稍后再试），细节只进事件流 | `reply` 卡死时对外只报了 "IM message has 109 words"；`im` 挂了只报 ENOTFOUND | `src/app/effects.ts` 的错误上抛处 + IM 桥的 `ERROR_COPY` 等价物 |
| 2 | **接收循环与推理分离 / ACK 语义**：收 → 校验 → 入队 → 立刻 ACK；推理另起任务 | 桥是逐行串行 `queue`，一行慢会压住后续行 | `src/sources/im-bridge.ts` 的 `lines.on('line')` |
| 3 | **心跳看门狗**：2.5×interval 没 tick 就强关重连 | 只靠子进程退出信号；半死连接会一直"在线" | 桥脚本 `/api` 侧，或 `im-bridge.ts` 加空闲计时 |
| 4 | **eventId 有界去重 + 命中只重发 ACK** | 桥把 message id 交给上层去重，但没有"重投只 ACK"的语义 | `im-bridge.ts` + `imTrigger` |
| 5 | **出站串行 + 帧上限（报错不截断）** | 多个 effect 并发写桥 stdio | `im-bridge.ts` 的 `sendIm` |

### P1 —— 让对话/交付质量上一个台阶

| # | 抄什么 | 为什么值 |
|---|---|---|
| 6 | **回复分段（1200 字）+ 首段策略（≥80 字或自然断句）** | 我们现在要么一次发完、要么被 100 词上限整条打回；分段能同时解决"太长"和"太慢" |
| 7 | **知识库（入口 + 命中 + 人工采纳）** | 我们完全没有跨工单的记忆沉淀；PR 里踩过的坑每次都靠重新读仓库 |
| 8 | **群背景缓冲（20 条 / 12h，明确"不要逐条回应"）** | `im`/`feishu` 里同事讨论半天，agent 只看到最后一条 @ |
| 9 | **六层诊断（DNS → TCP → TLS1.2 → TLS1.3 → 接口 → WS）** | 正是这次破案缺的工具；见 §0 |
| 10 | **延迟指标（ackP50 / firstP95 / slow-first / slow-total）** | 他们的原话："不能度量的承诺等于没有承诺" |

### 不建议照搬

- **进程内插件形态**：我们是独立插件 + 子进程桥，跨三种 IM（飞书/IM/Vanish）一致；换成进程内会
  把每种来源都焊死在 DSH 生命周期上。
- **v1 工具 allow-all**：他们在 DESIGN 里明确记了风险 R1（任何人 @ 就能读写工作区）。我们的工单
  本来就有 worktree 隔离与评审，不要退回去。
- **面板 UI 成本**：他们的 `client.js` 96 KB 是为了"值班室"这类可视化；我们的面板已经够用。

### 最值钱的是他们的验证手法，不是功能

| 手法 | 一句话 | 我们怎么用 |
|---|---|---|
| **假网关** | 自写 WS 网关跑"收消息 → 建会话 → 回复"全链路，一轮抓到两个致命 bug | 给 IM 桥写一个 `fake-bridge`：喂 JSONL、断言 ACK/去重/重连 |
| **桩 ctx 跑真实 handler** | 不启动连接就能测所有 HTTP 契约 | 我们的 `/orchestrator/api/*` 已有测试，可补"坏 token / 缺字段"分支 |
| **逐回合审计日志** | 直接解压会话日志，按回合数 `# 身份` 出现率，把"代码里写了"变成"日志里有" | 用它验"worker 每轮都带了交付要求"，而不是读源码 |
| **可缩短配置项** | `slackAfterMs` 默认 10 分钟，测试传 150ms | 我们的退避/冷却/超时都应可注入 |
| **前后对比审计** | 同一脚本量修复前后（未分组 2/0 → 2/2） | 修 workspace/来源时留证据 |

## 3. 逐项对照

| 关注点 | 他们 | 我们 | 结论 |
|---|---|---|---|
| 凭据位置 | 只在 `ctx.credentials`，状态文件绝不存 token | 桥脚本自己管（token 文件 `~/.secrets`） | 持平 |
| 连接健壮性 | 状态机 + 看门狗 + 闸门 + 串行写 + 帧上限 | 子进程重启 + 退避；无心跳、无去重 ACK | **抄** |
| 失败可见性 | 六层诊断 + 事件流 + 面板四档状态 | 健康项一句话（这次就是 ENOTFOUND） | **抄** |
| 回复长度 | 1200 字分段 + 首段策略 | 100 词上限，超了整条卡死（已修为入队校验） | **抄分段** |
| 记忆 | 知识库（入口 + 命中 + 人工采纳） | 无 | **抄** |
| 群上下文 | 20 条 / 12h 背景缓冲 | 只有被 @ 的那条 | **抄** |
| 多机多智员 | 12 个并发冷启动、4/s 闸门、错峰 300ms | 单实例多来源 | 观望 |
| 派工 | 替身 + 工人（文本标签协议） | dispatcher + worker 会话（结构化） | 我们更稳，不换 |

## 4. 行动清单（可直接开 ticket）

1. **`im` 源的失败要能指向动作**：`ENOTFOUND <内部网关>*` → 健康态写成
   "需要公司网络；当前 DNS 解析不到该网关"，而不是 `The bridge failed`。
2. **`scripts/diag-im.ps1`**：按六层输出 DNS / TCP 443 / TLS1.2 / HTTP 接口 / WS 握手 / 鉴权结果，
   每层给判据（这一层过了说明什么）。
3. **桥的 ACK 与去重下沉**：`im-bridge.ts` 收到行先校验+入队再 ACK；`eventId` 有界 LRU；
   重投只 ACK 不重跑。
4. **回复分段**：把 100 词硬上限换成"分段发送"（每段 ≤1200 字符，段间 400ms），
   保留"整条超限"作为最后一道闸。
5. **知识库最小版**：`~/.dsh/superagent/kb/entries/*.md` + 每轮入口块（≤1200 字）+
   命中才带正文 + 人工采纳的候选流。
6. **假桥测试**：`tests/im-bridge-fake.spec.ts` 覆盖 ACK/去重/断线重连/超长分段。

## 5. 附：两份文档里最有价值的三句话

1. **"零件级测试会集体变绿，但业务链路可以是全坏的。"**（VERIFICATION §14.1）
2. **"'代码里写了'不等于'生效了'。"**（persona 读错字段、preset 只记录不挂载、UI 选项没人消费）
3. **"不能度量的承诺等于没有承诺。"**（§13）

这三句和我们 `docs/014-progress.md` 里记的"验收要验到读者能感知的那一层"是同一件事的两侧写法。
